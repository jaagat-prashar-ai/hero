    1. Waypoints -> (accel, curvature) fit
    Where: action_space/unicycle_accel_curvature.py, UnicycleAccelCurvatureActionSpace.traj_to_action (lines 227-298), which calls
    _v_to_a (127-160) and _theta_v_a_to_kappa (152-205). The actual regularized solver is solve_xs_eq_y in action_space/utils.py (241-313).

    Pipeline (all under @torch.no_grad(), fp32-forced):
    1. theta = unwrapped heading from traj_future_rot, itself smoothed via a 3rd-order-Tikhonov single-point constrained solve (theta_smooth, utils.py: 491-514)
    2. v (velocity) solved from dxy/theta by trapezoidal integration constraint, 3rd-order smoothing, constrained to v0 estimated from history (dxy_theta_to_v, utils.py: 405-485)
    3. accel = dv/dt, solved via solve_xs_eq_y with 2nd-order Tikhonov smoothing (penalizes jerk-of-jerk, not jerk itself)
    4. kappa = dtheta / s where s = dt dot v + dt^2 / 2a (arc length), also 2nd-order smoothed, lam=kappa_lambda=1e-4, ridge=kappa_ridge=1e-4. 
    5. Both channels normalized: (x-mean) / std. 
    
    The regularized least-squares problem solved by solve_xs_eq_y (utils.py: 241-313):
    min_x sigma w_data_i (x_i dot s_i - y_i)^2 + lambda||D_k x||^2 + ridge dot ||x||^2

    solved as the normal equations (A^TA + D^TD + ridge dot I)x = A^Tb via Cholesky (construct_DTD, utils.py: 841-159, builds the banded difference-operator D^TD for order-1/2/3 smoothing).
