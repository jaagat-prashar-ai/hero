  # When the model produces a rollout (a driving plan plus a written explanation), the reward code does this: 
    # 1. Parse the explanation into individual claims. "I will decelearte because a pedestrian is crossing" becomes two checkable claims: decelerate (a claim about what the car will do) and pedestrian present (a claim about what's in the scene). 
    # 2. Verify each claim against ground truth. Each claim gets one of three verdicts: pass (checked, true), fail (checked, false), or abstain (we simplt can't check it -- e.g., our dataset has no ground truth for traffic cones, so a claim about cones is unjdudgeable). TO-DO, HOW DO WE FIX THIS?
    # 3. Score with precision: r = passes + (passes + fails), counting only the claims we could check. If 3 claims were checkable and 2 passed, r = 0.67. 
    # 4. Coverage-blend (yesteraday's work): decided_fraction (df) is the share of claims we should check. The blended score is r_eff = df*r + (1-df)*0.8. In words: the aprt of the trace we could check contributes its measured precision; the part we couldn't check contributes a fixed benefit-of-the-doubt value of 0.8. 
    # The reasonign_score = r_eff - 1, shifting it ot the range -1.0 where 0 is the best. 

    # How do we get this 0.8 benefit of doubt value? 
    # The 0.8 benefit-of-the-doubt value corresponds to a reasoning_score of -0.2. The more of a trace we couldn't check, the more its score is dragged oward that -0.2, no amtter how good or bad the checkable part was. 

    # Concrete example: a trace where we could only check 30% of the claims (df=0.3): But how do we parse more than 2 claims here? assuming commitment and perceptual as defaults?
    # Even if every checkable claim was true (r=1): score = 0.3*1 + 0.7*0.8 - 1 = -0.06. Can't reach 0. 
    # Even if every checkable claim was false (r=0): szcore = 0.3*0 + 0.7*0.8 -1 = -0.44. Can't reach -1. 

    # So a mostly-uncheckable trace gets squeezed into a narrow band around -02. It can't be scored as excellent or terrible. That's deliberate: we only measured a third of it, so we shouldn't, so we shouldn't make strong statements either way. A fully-checkbale trace (df=1) still spans the whole -1.0 range.
